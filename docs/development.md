# 實作與修改紀錄

以下保留早期原型的修改過程。第一版目前已加入完整對局，見下方「第三階段」與 [對局驗收](game-validation.md)。

## 字形物理原型

參考姓名戰鬥陀螺及 Moji Blade 的字形與字體概念，由 GPT-6 Astra 蒸餾物理要求與必要測試，再由主實作者調整為本專案的翻面玩法。

本階段可操作流程：輸入文字／emoji → 選字體 → 產生 3D 薄片 → 點選施力位置 → 撬起或落下撞擊 → 觀察停止後的面向。

三個屬性為重量、穩定度、翻轉靈敏度；來源、公式與近似限制見 [物理蒸餾](physics-distillation.md)。三幣開局、奪幣、電腦與勝負仍是後續工作，不以此原型冒充完成對戰。

## 實際調整

- 原型起初將碰撞格作為可見模型，改為背景方盒碰撞與前景輪廓擠出；預覽亦改為完整文字／emoji。
- 保留字形孔洞、獨立筆畫與 emoji 正面色彩，正背面有不同材質。
- 原先合計線速度與角速度的停止條件改為分別檢查，並要求桌面真實接觸，避免空中或動態誤判。
- 手機尺寸檢查發現面板被 WebGL 畫布撐寬，修正網格子項最小寬度後確認無水平溢出。
- 字體載入逾時或失敗時改用替代字體，並以同一實際字形繪製與計算。

## 已執行驗證

- [獨立物理驗收](../tests/physics.cjs)：六組全部通過，涵蓋解析矩形、非對稱 L 形、密度及覆蓋率、施力槓桿、停止判面與測試球碰撞。
- 程式語法檢查通過；測試瀏覽器沒有頁面執行錯誤。
- 實際瀏覽器操作確認 Noto 黑體／明體的取樣質量不同，emoji 可產生模型，空白輸入會提示。
- 撬起測試的初始角速度符合獨立剛體公式；落下測試球與薄片產生真實接觸。
- 已檢視桌面 1200px 與手機 390px 畫面；完整字形可見，碰撞格未顯示，手機沒有水平溢出。
- 測試檔由 Astra 定義，主實作者核對 SHA256 後執行，未改動測試預期。

## 重現方式與限制

以靜態網頁伺服器在 `http://127.0.0.1:5173/` 提供專案，開啟 `index.html` 即可操作。獨立測試以 `node tests/physics.cjs` 執行；目前沿用開發裝置既有的 Playwright 套件與 Chrome 絕對路徑，其他裝置需由測試維護者調整執行環境，不更改驗收條件。

原型初次開啟需網路載入函式庫與網路字體。裝置字體與 emoji 可因環境不同而產生不同物性；碰撞格與顯示輪廓具有取樣近似誤差。高速薄片互撞、完整對戰、出界等尚未驗證。

## 第二次物理調整：邊緣與攻守平衡

- 依使用者確認，邊緣及小接觸面積提供撬起加成；彈起不等於淘汰，落地停止後反面才算。
- 加成透過真實衝量與力臂施加，含平移、旋轉及既有速度交叉項的動能增量上限為 0.12 J；同一次撞擊只加成一次。
- 字形覆蓋率增加時，互補預算的防守配置上升、進攻配置下降；真正防守由剛體角耗散作用，進攻由總投擲能量作用。
- 加入「投擲此字形」：操作的是字形本身，不以固定球代替攻方。高度位能與平移動能共用預算，且具速度／衝量上限。
- 原六組物理驗收保持通過；Astra 新增的 [攻守與邊緣測試](../tests/balance.cjs) 八組全部通過。
- 攻守配置不能同時最高，但字形與碰撞仍有策略差異；目前不宣稱所有 Unicode 字形或配對勝率已達平衡，完整對局驗證仍待下一階段。

## 第三階段：第一版可玩成品

- 介面改為簡潔淺色，預設是對戰設定；物理測試保留為獨立入口。
- 各玩家設定名稱、三枚字形及字體，支援單人對電腦及單機雙人。
- 接通手上優先、桌面重投、命中接觸鏈、背面捕獲入手、物性保留、多枚同時奪取及僅6：0勝利。
- 桌面點擊／觸控瞄準、力度滑桿與鍵盤微調；藍／橘側邊顯示目前主人。
- 電腦依對手的穩定度與質量傳遞估計選枚；難度只改力度與瞄準誤差，實際投擲和真人相同。
- 完整試玩發現逐格碰撞配對過慢，將相鄰完整行段合併為不填洞的碰撞矩形，質量與主軸慣量仍由原像素積分。
- 完整試玩發現只瞄準桌面中央與反覆使用同一輕字容易拖長對局，擴大桌邊瞄準範圍並改進電腦選枚。
- 啟用對局自動休眠，保存真實支撐及姿態證據；拿起或移除下層時喚醒並清除紀錄。超時不得把未落地、側立或仍在移動的枚算成奪取。
- 手機檢查修正 Canvas 撐寬、三個輸入格溢出及窄畫面相機裁切；整張桌面可見。
- Astra 的對局測試增至17組，與原物理6組、攻守8組合計31組通過。涵蓋實際接觸與延後助推、整體能量、密度攻守單調關係、高處桌邊碰撞、安全出生、合併區遮罩及休眠轉折。出生預檢加入後，由測試作者修正原本會重疊的接觸準備位置，保留原規則斷言。
- 正式對局以覆蓋率限定材質重量，保留形狀、重心與像素質量比例；修正稀疏字因速度上限反而難以進攻的問題。邊緣助推同樣依攻方進攻份額限制完整動能增量。
- 長局觀察發現壓顶接觸會抵消同一步的邊緣助推，改為保存真接觸並在求解完成後施加；同時加高、加厚桌邊實體牆，避免薄片飛到無法瞄準的位置。沒有強制翻面或改寫所有權。
- 發現投擲出生點可能與既有疊牌重疊，加入八個方向的實際包圍盒預檢；無安全候選時不拿走桌面枚、不換回合。電腦輪替八個方向試探外緣，減少重複打同一點。
- 已透過真正拋擲、碰撞及結算觀察自然捕獲與奪回；6：0勝負另有獨立完整生命周期驗收。字體、對手配置及玩家選點會改變對局長度，尚不宣稱所有字的胜率相等。

第一版部署於 [GitHub Pages](https://miudog.github.io/ong-a-piau/)，主程式仍為單一 `index.html`。規格獨立放在 `docs/specification.md`，Git 提交保存每次主要實作與修正。

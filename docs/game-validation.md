# 可玩第一版：對局驗收契約

本文件只定義已確認玩法及必要驗收。原有字形質量／慣量、攻防預算及邊緣助推的保護測試持續適用；不能為了讓對局通過而改其预期。

## 不變量

1. 開局恰有六枚不同 id 的薄片，兩位玩家各持三枚；每枚只存在於一個位置。body 為 null 表示手中，非 null 表示桌面或正在飛行。
2. 持有數永遠是手中枚數加桌面枚數，不以桌面數或手牌數單獨判勝。一般回合不得創造、複製或遺失薄片。
3. 有手中枚時只能投擲手中枚；沒有手中枚時才可撿起自己的桌面枚。不能選對手的枚，也不能在模擬中再次投擲。
4. 捕獲只作用於本次攻方實際碰撞或接觸連鎖影響的對手枚。自己投出的枚即使背面落地，也不能被自己的動作捕獲。
5. 對手枚只有在最終背面朝上、具有傳至桌面的真實接觸支撐且已停止後，才轉移到攻方手中。支撐可直接接觸桌面，或經其他已停止的薄片傳到桌面；只有薄片相互接觸、整組仍在空中不算支撐。空中瞬停、側立、仍在移動、超時未定及最後正面朝上均不算捕獲。不能因為曾彈起或曾朝下而判成功。
6. 同次投擲可捕獲多枚。捕獲保留 id、文字、字體、形狀模型、質量、重心、慣量與攻防物性，只轉移所有權和辨識顏色，並移除被捕獲枚的桌面剛體／展示物件。
7. 只有六比零可勝利；五比一不能結束。先處理本回合所有捕獲及勝利，再切換下一位玩家，避免捕獲判給下一位。
8. 電腦必須遵守相同選枚和力度限制，透過相同真實拋擲／接觸／結算路徑行動；不能直接指定翻面、修改所有權或抽籤決勝。
9. 重開對局會清除舊桌面物件與待執行電腦行動。舊非同步字體載入、舊計時器或舊回合回呼不得改写新對局。

## 必要測試範圍

[tests/game.cjs](../tests/game.cjs) 由測試作者維護。實作者可讀取與執行，不能修改 assertion、fixture、跳過條件或預期結果。

驗收以實際瀏覽器中的產品模組與物理世界為主。可設置薄片位置與姿態來隔離結算条件，但必須透過 world.step 取得真實桌面接觸；至少一案必須經過實際剛體碰撞、命中標記及捕獲，不能只把 hit 設為 true 代替完整流程。

| 驗收主體 | 必須保護的結果 |
| --- | --- |
| 開局及合法選枚 | 六個唯一 id、每人三枚；手中優先、對手不可選、模擬中不可重複出手。 |
| 回合及重用 | 投出手中枚變為物理桌面枚；沒有手中枚時可投自己的桌面枚；回合交替。 |
| 真實命中結算 | 真實碰撞標記受影響對手；停止且背面接觸桌面後捕獲到攻方手中。 |
| 排除及多枚捕獲 | 未命中、正面、側立、空中或仍在動均不可捕獲；兩枚可同時捕獲。 |
| 身份及勝負 | 捕獲前後模型与身份不變；總枚數六；五比一繼續，六比零才勝利。 |
| 電腦及重開 | 電腦計畫合法且沒有直接改持有權；重開清除舊狀態及舊剛體。 |

電腦計時器測試只在結算時保存產品真正安排的回呼，分別手動觸發同一局回呼及重開後的過期回呼，檢查真實投擲與世代隔離；不以等待任意秒數取代驗收。側立案例先取得真實桌面接觸，空中案例包含兩片互相接觸，避免錯誤原因被「根本沒有接觸」掩蓋。

真實捕獲案例安排對手以背面躺地，再讓攻方薄片真正接觸它，驗證碰撞標記、支撐、捕獲與下次重投。這能隔離生命周期錯誤，但不宣稱任意自然拋擲都能翻面；從開局到終局的實際操作與玩法可行性仍需整體試玩驗證。

## 與既有驗收整合

tests/physics.cjs 保護解析質量、重心、慣量、施力、真實接觸與靜止判面。tests/balance.cjs 保護攻防能量分配、角阻尼、發射實際能量與有限邊緣助推。對局測試負責枚的生命週期、權屬與規則，不以重複大量物理公式測試取代流程驗收。

介面外觀、淺色樣式、手機觸控及 GitHub Pages 的正式網址另由畫面與發佈驗證確認；本文件不把程式測試通過誤稱為完整視覺或遠端發佈通過。

2026-10-13 已執行本文件的七組遊戲驗收，全數通過；同次重跑原六組物理與八組攻防驗收亦全數通過。測試使用各自獨立瀏覽器頁面與實際產品模組，不共享對局狀態。
